## 2025-02-23 - Prevent Stored XSS from EJS JSON Stringification
**Vulnerability:** Directly injecting `<%- JSON.stringify(...) %>` into `<script>` tags without escaping the output introduces a Stored XSS vulnerability. If the JSON data contains `</script><script>alert(1)</script>`, it breaks out of the script context and executes arbitrary JavaScript.
**Learning:** EJS `<%- ... %>` outputs raw strings. The proper way to inline JSON data into a `<script>` tag is to replace the characters `<` and `>` with their unicode equivalents. Crucially, when patching EJS files with Python or other script-based tools, the replacement string must literally contain the double backslash `\\u003c` in the `.ejs` file so that Node.js outputs the literal string `\u003c` to the browser, neutralizing the script breakout without breaking the JSON parser.
**Prevention:** Always use `<%- (JSON.stringify(data) || 'null').replace(/</g, '\\u003c').replace(/>/g, '\\u003e') %>` when injecting server-side data into client-side scripts. Use an `escapeHtml()` function for `innerHTML` assignments in client-side code.
